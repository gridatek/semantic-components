- [ ] **Date bounds from the form, once Angular takes them** (the user, 2026-11-20) — Calendar, Date Picker, Date Input and Segmented Date Input keep `minDate` / `maxDate` inputs: Signal Forms' `min()` / `max()` validators take numbers only (`TValue extends number | null`), though its metadata already holds `Date | number` (`MIN` / `MAX`), and Temporal isn't in either. When `min()` / `max()` accept dates (`Temporal.PlainDate`), move them to the rule "Bounds Come From the Form" (docs/component-design-principles.md) and **remove `minDate` / `maxDate`**: with a form, the bounds in the schema (for a range value — Calendar's, Date Picker's — on each date, as the Range Slider's `applyEach`); without one, `[min]` / `[max]` (as the Range Slider's `minInput` / `maxInput`, aliased, if Signal Forms types `min` as the value). The demos, READMEs, docs pages and tests with them; the code is marked `TODO(angular): minDate / maxDate go` at each pair. Angular's issue: [angular/angular#67643](https://github.com/angular/angular/issues/67643) ("Signal Forms: Support of Temporal types for min/max validators", open since 2026-03-12, no PR as of 2026-11-20) — the team leans to structural types that fit Temporal values (no dependency on its typings), as Angular Components' Temporal date adapter does ([angular/components#32668](https://github.com/angular/components/pull/32668)).
